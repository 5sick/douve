# 보안 모델 (요약)

전체 내용과 취약점 신고 방법은 [SECURITY.md](../SECURITY.md)(영어)를 보세요.

## 신뢰 관계
- **Hub가 가장 중요합니다.** Hub(또는 방금 패스키를 확인한 로그인 세션)를 가진 사람은 모든 서버의 터미널을
  열고 라우팅·Agent 업데이트를 보낼 수 있습니다. Hub 서버는 비밀번호 관리자처럼 다루세요.
- **모든 사용자가 전체 관리자입니다.** 아직 역할 구분이 없으니 root를 줄 수 있는 사람만 초대하세요.
- **외부 보안 감사 전입니다.** WebAuthn 검증·CBOR/COSE 파싱·세션은 이 저장소(C++)에 직접 구현했고
  단위·E2E 시험(실제 브라우저 가상 인증기)이 있지만, 퍼징이나 외부 감사는 아직입니다.

## 원칙
1. **비밀번호 없음** — 패스키가 기본, Google 로그인은 허용 목록 한정 선택 사항. 첫 관리자는 서버에서
   출력한 일회용 초대 링크(토큰은 URL # 뒤라 로그에 남지 않음).
2. **재인증** — 설정·서비스·초대·복구 코드는 5분, 터미널은 60초 안에 패스키를 다시 확인.
3. **최소 노출** — Hub는 127.0.0.1에서만 받고, 서버의 Agent는 들어오는 포트를 열지 않는다(밖으로 연결).
4. **fail-closed** — Hub에 닿지 않으면 로그인이 필요한 앱은 막고, 공개 앱만 저장된 표로 계속.
5. **감사** — 로그인, 재인증, 설정 변경, 터미널(화면 녹화), 노드에서의 공개를 기록.
6. **세션** — 서버에 저장, DB에는 토큰의 SHA-256만. `HttpOnly; Secure; SameSite=Lax`, 같은 기기 재로그인 시 교체.
7. **입구** — 보호 앱으로 넘기기 전에 `douve_session` 쿠키와 클라이언트가 보낸 `X-Douve-User`·`Tailscale-*`
   헤더를 지우고 `X-Douve-User`를 직접 붙인다. HSTS.

## 구현 시 주의 (C++)
- WebAuthn 서버 검증은 직접 구현 → 시험 필수 (CBOR, COSE 키, 서명, rpIdHash, origin, signCount, UV).
- Google ID 토큰: JWKS 서명 검증 + `iss`/`aud`/`exp`/`email_verified`.
- 상태를 바꾸는 요청은 Hub 자신의 origin에서만 (CSRF), 화면은 CSP `script-src 'self'`.
- 보안 관련 코드는 시험 없이 머지하지 않는다.
